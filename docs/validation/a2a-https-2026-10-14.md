# A2A HTTPS deployment validation — 2026-10-14

Base: `origin/main` at `b2d5c77`; work branch: `codex/hermes-tools-a2a`.
Runtime: Hermes 0.21.0 (`29112bef09`), Python 3.11.15, MCP 2.0.0,
Codex CLI 0.159.2. This record intentionally excludes real hostnames, QQ
identifiers, bearer tokens, private keys, and private conversation history.

## Deployment

Three existing profiles (`default`, `product`, `procurement`) were deployed on
one Mac using separate Gateway processes. Their A2A listeners bind only to the
host's Tailscale address, on ports 19901/19902/19903 respectively. HTTPS URLs
use the existing full Tailscale node hostname and `/default`, `/product`, or
`/procurement` suffixes. Each listener uses a private-CA-signed certificate;
clients verify both the chain and hostname. All six directed peer pairs have
separate bearer credentials and explicit trusted identities.

The bundled `a2a-platform` registration is disabled. The removable
`a2a-https-hotfix` registers the upstream protocol with a native TLS listener
and HTTPS-only outbound requests, including push callbacks. There is no HTTP
proxy hop in the A2A path. The existing Tailscale Serve management route was
compared before/after and left unchanged.

The profile's Codex `hermes-tools` entry now uses the persistent startup
wrapper and explicitly forwards `HERMES_HOME`. Other MCP settings and timeout
values are retained. Fresh MCP processes expose all five A2A tools for each
profile. Ordinary Codex sessions without `HERMES_HOME` retain their upstream
tools with A2A withheld; they do not accidentally use the default profile's
A2A peers.

Backups were created before mutation. Existing `.env` entries and unrelated
Hermes YAML/Codex TOML values were compared semantically after deployment and
matched. No QQ, Codex, WeKnora, or other existing credential was replaced.
New A2A secrets, certificate files, and backup files remain in owner-controlled
runtime directories. Gateways were restarted only after an idle check, using
the upstream SIGUSR1 drain/restart path; all three reconnected to QQ and A2A.

## Checks and observed results

- 7 startup-wrapper unit tests passed.
- 5 TLS-policy tests passed: certificate/hostname verification, HTTP and
  redirect rejection, fail-closed missing material, origin pinning, and the
  reserved default-profile path.
- 4 integration tests passed with real Hermes/MCP processes, temporary TLS
  peers, and an actual Codex app-server tool-call RPC. These cover the five
  handlers, profile isolation, auth refusal, and unscoped Desktop compatibility.
- All six directed production peer pairs passed HTTPS certificate validation
  and authenticated, non-model A2A requests.
- Each production listener rejected plaintext HTTP and an HTTPS connection
  without the private CA trust anchor.
- Fresh deployed MCP inventories exposed five A2A tools per profile and no
  A2A tools to an unscoped Codex client, while keeping legacy tools available.

Real QQ messages were sent from the operator's client in the operator-selected
test group. Three complete request/reply chains passed:

| Originating QQ profile | A2A target | Test marker | Exact target reply returned to the original group |
|---|---|---|---|
| default | product | A2A-QQ-D3-1014 | Product received support team test 1014 |
| product | procurement | A2A-QQ-P3-1014 | Procurement received product test 1014 |
| procurement | default | A2A-QQ-C2-1014 | Default received procurement test 1014 |

For each row, the actual MCP `a2a_call`, receiving profile's A2A session,
complete target answer, originating QQ session's final answer, and visible
QQ reply were checked. This is a three-edge ring covering each profile as both
caller and receiver, not six successful model-to-model QQ round trips.

## Findings and limits

1. Early nested model requests received upstream **429 Too Many Requests**.
   Hermes sometimes classified those failures as expired login because its
   OAuth classifier also examines stderr. The raw Codex completion records
   established 429; credentials were not changed. Final QQ checks waited
   60 seconds before one A2A call and passed. This does **not** establish a
   general concurrency limit or guarantee that future bursts will avoid 429.
   No automatic retry loop, quota reset, or model substitution was added.
2. Upstream Gateway streaming could strip a delivered-looking prefix from
   an A2A result even though the adapter ignores non-final previews. The
   target's `Product received ...` was observed as `received ...` at the caller.
   Setting only `display.platforms.a2a.streaming: false` and
   `interim_assistant_messages: false` restored exact full replies, verified
   first through HTTPS and then in QQ. Other platforms' streaming is unchanged.
3. Only these three profiles on this Tailscale node were deployed. Other hosts
   still need the public CA certificate, peer credentials, a configured HTTPS
   URL, and permitted tailnet connectivity. Cross-host acceptance was not run.
4. Leaf certificates expire one year after issuance; renewal and an idle
   Gateway restart are required before expiry. No automatic renewal service
   was installed.
